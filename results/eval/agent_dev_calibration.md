## Does the confidence signal support a threshold at all?

The model reports 2 distinct confidence value(s) on dev: 0.90, 0.95.

| confidence | items | state+intent correct |
|---|---|---|
| 0.90 | 3 | 1.00 |
| 0.95 | 37 | 0.81 |

**7 of the model's errors carry its highest confidence value.** Self-reported confidence therefore does not separate correct from incorrect routing on dev, so policy rule (h) — escalate when confidence is low — has nothing to key on. Any threshold at or below the minimum observed value is inert; a threshold above it escalates the *most* confident items, which is worse than useless.

**Chosen: cues = model+extractor, threshold = 0.0** (highest joint routing on dev, escalation recall breaking ties). At this value rule (h) never fires, which is deliberate: the rule stays in the policy for a future confidence signal that actually carries information (token logprobs or self-consistency), to be developed on dev.
